## Bazy relacyjne w sieci wewnętrznej

Relacyjne systemy baz danych wymagają uwierzytelnienia, lecz w sieci wewnętrznej często zachowują konta domyślne lub puste hasło administratora. MySQL nasłuchuje na porcie 3306, PostgreSQL na 5432. Rozpoznanie zaczyna się od skryptów NSE, potrafiących dla MySQL wprost wykryć puste hasło konta uprzywilejowanego.

```bash
sudo nmap -p 3306 --script mysql-info,mysql-empty-password,mysql-variables -Pn [IP]
```

`[IP]` adres badanego hosta.

```text
3306/tcp open  mysql
| mysql-info:
|   Version: 8.0.34
| mysql-empty-password:
|_  root account has empty password
```

## Próba domyślnych poświadczeń

Gdy skrypt nie wykaże pustego hasła, sprawdza się ograniczony zbiór domyślnych par, osobno dla każdej usługi. Postępuje się zgodnie z zasadą z lekcji o poświadczeniach: liczbę prób ogranicza się, a wynik potwierdza kontrolą negatywną.

```bash
hydra -L [USERS] -P [PASS] -I -t 2 -w 15 postgres://[IP]
```

`[USERS]` plik z nazwami kont · `[PASS]` plik z hasłami · `[IP]` adres hosta.

## Interpretacja

Puste hasło konta uprzywilejowanego lub przyjęcie domyślnej pary to ekspozycja usługi bazodanowej, otwierająca dostęp do danych. Samo rozpoznanie wersji bez potwierdzonego logowania pozostaje jedynie informacją o usłudze. Ograniczenie ryzyka polega na usunięciu kont domyślnych, wymuszeniu silnych haseł oraz na ograniczeniu dostępu sieciowego do bazy.
